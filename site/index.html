Prove what cloud credentials, and the AI agents holding them, can actually reach.

Reach turns AWS IAM policies into constraints for the Z3 solver. Every DENIED is a proof, and every ALLOWED comes with a concrete request, re-checked by an independent evaluator and validated against AWS's own policy simulator. Then it maps each AI agent to the credentials, tools and text it can reach, and flags the ones that can be talked into sending your data out.

Three verdicts, and none of them is a guess

Policy linters match patterns. Reach asks the solver whether any request in the whole space of actions, resources and request contexts gets through identity policies, permissions boundaries, SCPs, RCPs, session policies and resource policies together.

ALLOWED

Comes with a witness: the exact action, resource and context keys of a request that gets through. Before it is shown, a second, solver-free evaluator replays it.

DENIED

A proof: no request satisfies the policies (UNSAT). Reach also says why: an explicit Deny, a boundary, an SCP layer, or no grant at all.

UNKNOWN

When an answer depends on something Reach does not model, it says so and names the assumption, instead of rounding it to a yes or a no.

$ reach can --authz authz.json --principal agent-dev s3:PutObject arn:aws:s3:::goat-uploads/report.csv
ALLOWED  s3:PutObject on arn:aws:s3:::goat-uploads/report.csv
  principal  arn:aws:iam::123456789012:user/agent-dev
  witness    s3:PutObject on arn:aws:s3:::goat-uploads/report.csv
             aws:SourceIp = "203.0.113.0"

$ reach can --authz authz.json --principal agent-dev iam:CreateAccessKey '*'
DENIED  iam:CreateAccessKey on *
  principal  arn:aws:iam::123456789012:user/agent-dev
  proof      no request context satisfies the policies (UNSAT)
  why        No identity-based or resource policy grants any action matching iam:CreateAccessKey.

How it works

The encoding is exact where AWS's behaviour is known, and every unknown is explicit, so a proof never rests on a guess.

Load

An account snapshot, an Organizations export (SCP and RCP tree), resource policies, and agent configs on the machine or in CI.

Group

22,080 real actions from AWS's Service Authorization Reference, split into classes every policy treats alike, one solver problem per class and resource type.

Encode

ARNs segment by segment, typed condition keys (strings, 128-bit IPs, exact decimals, times, bounded sets), policy variables substituted symbolically.

Solve

Z3 checks the optimistic and the worst case, so unmodelled conditions can block a proof but never fake one.

Check

Every witness is replayed by a second evaluator, and the two are fuzzed against each other and against AWS.

The agents holding the credentials

An agent that reads text an attacker wrote, can reach private data, and can send data out can be instructed to leak it. Simon Willison calls this the lethal trifecta. Reach finds it, leg by leg, from evidence.

  • Agents and tools: Claude Code, Claude Desktop, Cursor, VS Code, Windsurf, and AI agents in GitHub Actions, with their MCP servers, shell mode and pre-approved commands.
  • Credentials: what each tool is handed and what any shell can read, never printing a secret. AWS profiles are resolved and run through the engine.
  • Planted instructions: instruction files, skills, subagents and local MCP servers' tool descriptions are checked for tool poisoning, with Husk for whole files.
  • In CI: SARIF for GitHub code scanning, pointing at the line that causes each finding.

Checked against AWS, not against the docs

Documentation leaves edge cases open. Reach measures them on AWS's policy simulator, models what it sees, and records each result with the probe that found it. Some of these were Reach bugs; some are AWS behaviour nobody had written down.

RCPsA Deny on s3:GetObject says nothing about s3:PutObject; actions an RCP treats differently are now never grouped. Found by the fuzzer in CI.
NumbersBigDecimal syntax, compared exactly: 9007199254740993 is not 9007199254740992, and an invalid value fails every operator, NumericNotEquals included.
Ignore caseFull Unicode lowercase: the Kelvin sign matches k, but long s does not match s, although Java's rule says it does.
IPv6Families never mix: 0.0.0.0/0 matches no IPv6 source, and ::ffff:10.1.2.3 counts as IPv4.
BoolAny letter case of true is true and everything else is false, for every key.
BinaryBase64 is compared as text: YWI= and YWJ= differ, though both decode to ab.
SimulatorFor same-account grants to the account principal, AWS's simulator is wrong; a live S3 test settled it.

Run it everywhere

  • One question: reach can with a policy file or an account snapshot.
  • A whole account: reach audit, in parallel, with a matrix, JSON or HTML.
  • An organization: --org applies the SCP and RCP tree from a read-only export.
  • Every pull request: the GitHub Action uploads findings to code scanning.
# .github/workflows/reach.yml
permissions:
  contents: read
  security-events: write
steps:
  - uses: actions/checkout@v7
  - uses: ctrl-adam/Reach@v0.2.1
    with:
      fail-on: critical
