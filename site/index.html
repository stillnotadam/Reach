Features

Answers you can check, not findings you have to trust.

Reach asks whether any request, across every action, resource and request context, gets through identity policies, boundaries, SCPs, RCPs, session policies and resource policies together.

Three verdicts, no guesses

When Reach cannot decide something, it says what the answer depends on instead of rounding it.

ALLOWEDwith a witness request, replayed by a second evaluator
DENIEDa proof: no request satisfies the policies
UNKNOWNnames the condition it depends on

The agents holding the credentials

Claude Code, Cursor, VS Code, Windsurf and AI agents in GitHub Actions: their MCP servers, shell mode, pre-approved commands and the credentials each can use. Agents that combine untrusted input, private data and a way out get flagged, with the cheapest leg to break.

CRITICALClaude Code in triage.yml: issue comments, a deploy key, a write token

Tool poisoning

Tool descriptions, skills and instruction files are checked for planted instructions, with Husk for whole files.

Organizations

SCPs from the root down to the account, RCPs with every documented exemption, and the org context keys.

Whole accounts

Every user and role against the high-impact questions, in parallel: 45,000 decisions in 40.5 s.

Exact where AWS is known

ARNs segment by segment, 128-bit IP addresses, exact decimals, Unicode case folding, bounded sets for multi-valued keys, and policy variables substituted symbolically. 22,080 actions are grouped into the few classes the policies actually distinguish, so * queries take milliseconds.

CI native

A GitHub Action that uploads SARIF to code scanning, pointing at the line behind each finding.

Usage

One question, one account, or every pull request.

Point Reach at a policy file or at an account snapshot from aws iam get-account-authorization-details. It never calls anything that changes your account.

$ reach can --authz authz.json --principal agent-dev s3:PutObject arn:aws:s3:::goat-uploads/report.csv
ALLOWED  s3:PutObject on arn:aws:s3:::goat-uploads/report.csv
  principal  arn:aws:iam::123456789012:user/agent-dev
  witness    s3:PutObject on arn:aws:s3:::goat-uploads/report.csv
             aws:SourceIp = "203.0.113.0"

$ reach can --authz authz.json --principal agent-dev iam:CreateAccessKey '*'
DENIED  iam:CreateAccessKey on *
  principal  arn:aws:iam::123456789012:user/agent-dev
  proof      no request context satisfies the policies (UNSAT)
  why        No identity-based or resource policy grants any action matching iam:CreateAccessKey.

Validation

Checked against AWS, not against the docs.

Documentation leaves edge cases open. Reach measures them on AWS's policy simulator, models what it sees, and keeps the probe that found it.

RCP action classes
A Deny on s3:GetObject says nothing about s3:PutObject. Found by the fuzzer in CI and fixed in 0.2.1.
Numbers
Compared exactly: 9007199254740993 is not 9007199254740992. An invalid value fails every operator, NumericNotEquals included.
Ignore case
Full Unicode lowercase: the Kelvin sign matches k, but long s does not match s, although Java's rule says it does.
IPv6
Families never mix: 0.0.0.0/0 matches no IPv6 source, and ::ffff:10.1.2.3 counts as IPv4.
Binary
Base64 is compared as text: YWI= and YWJ= differ, though both decode to ab.
Simulator
For same-account grants to the account principal, AWS's own simulator is wrong. A live S3 test settled it.
