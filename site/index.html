Ask what a credential can do. Get a proof, or the request that gets through.

Reach reads AWS IAM policies, permissions boundaries, SCPs, RCPs and resource policies, and decides each question with the Z3 solver. It also finds the AI agents on a machine or in CI that hold those credentials, and flags the ones an attacker could instruct to send data out.

    What it checks

    Identity and resource policies
    Identity policies, permissions boundaries, session policies, bucket and key policies, and role trust policies, with same-account and cross-account rules.
    Organizations
    SCPs from the root down to the account and RCPs with every documented exemption, from a read-only export of the organization.
    Conditions
    Strings, ARNs, IPv4 and IPv6 ranges, exact decimals, dates, case-insensitive text, base64, and the ForAnyValue and ForAllValues set operators, each as AWS evaluates it.
    Whole accounts
    Every user and role against nine high-impact questions, in parallel, as a terminal matrix, JSON or an HTML report.
    AI agents
    Claude Code, Cursor, VS Code, Windsurf and agents in GitHub Actions: their MCP servers, shell mode, pre-approved commands and the credentials each can use, and whether one agent combines untrusted input, private data and a way to send data out.
    Planted instructions
    Instruction files, skills and MCP tool descriptions checked for tool poisoning, with Husk for whole files.

    How a verdict is reached

    A question such as s3:* on * ranges over thousands of actions, every resource and every request context at once. Reach answers it in five steps, and each answer carries its evidence.

    1. Load the policies.An account snapshot from get-account-authorization-details, plus any organization export and resource policies.
    2. Group the actions.22,080 real actions from AWS's Service Authorization Reference, split into the few classes the policies actually treat differently.
    3. Encode them for the solver.ARNs segment by segment, and every condition key in its own type, so a wildcard cannot cross a colon and 10.0.0.0/8 never matches an IPv6 address.
    4. Solve twice.Once assuming unmodelled conditions help the request and once assuming they block it. A request allowed in both is ALLOWED; one allowed in neither is DENIED; anything else is UNKNOWN, with the assumption named.
    5. Check the answer.The example request is replayed through a second evaluator that shares no code with the solver. If they disagree, Reach reports an error instead of a verdict.

    Measured on AWS

    The IAM documentation leaves edge cases open. Reach sends them to AWS's policy simulator, models the result, and keeps each probe in the repository so the measurement can be repeated.

    In CI

    The GitHub Action scans the repository's agents and workflows and uploads the findings to code scanning. Each alert points at the line that causes it, and no secret value is written to the report.

    .github/workflows/reach.yml

    permissions:
  contents: read
  security-events: write
steps:
  - uses: actions/checkout@v7
  - uses: ctrl-adam/Reach@v0.2.1
    with:
      fail-on: critical   # fail the job on a critical lethal trifecta
